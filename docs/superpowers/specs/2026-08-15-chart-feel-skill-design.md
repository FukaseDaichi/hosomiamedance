# 譜面改善スキル「chart-feel」設計書

2026-08-15

## 目的

音ゲー譜面の「気持ち良さ」を、既存の言語化された譜面理論(osu! mapping wiki 等)から
このゲームに適用できる形で蒸留し、それを基準に `src/charts.json` を改善する
プロジェクト専用スキルを作る。

- 対象はこのリポジトリの譜面のみ。汎用スキルにはしない
- 自分の体感には頼らず、既存理論に当てはめる方針
- スキルは改善実行型: 診断 → `bake-chart.py` 修正 → 再 bake → 検査までを一気に行う
- 合格基準は自動検査(理論をメトリクス化したもの)。人間のプレイ確認は必須としない

## 成果物とファイル配置

```
.claude/skills/chart-feel/
├── SKILL.md          # 手順書(改善ループの回し方)
└── theory.md         # 理論リファレンス(原則5〜7個)
scripts/bake-chart.py # verify() に理論由来の検査を2〜3個追加
AGENTS.md             # プレイ確認の文言を削除し、スキルに言及
```

新規スクリプトは作らない。検査は既存の `verify()` / bake フローに乗せる。

## 調査

- 主軸は osu! mapping wiki(用語集・Ranking Criteria 周辺)。必要なら 4 キー系
  (osu!mania 4K / DDR)の譜面理論を 1 ソースだけ追加
- このゲームに存在しない概念(ロングノーツ、スライダー、変拍速演出)は最初から捨てる
- 調査結果はそのまま残さず、theory.md に蒸留して終わり

## theory.md

各原則は「名前 / 定義 / このゲームでの意味 / 検査可能か」の数行で書く。初期候補:

| 原則 | 一言で | 検査 |
| --- | --- | --- |
| 音付け | ノーツは実際に鳴っている音に対応する | 可(オンセット近傍率) |
| 密度カーブ | 曲の盛り上がりと密度が一致する | 可(セクション別密度) |
| 休符設計 | 高密度の後に休みを置き、緩急を作る | 可(高密度連続長の上限) |
| 反復の抑制 | 同一パターンの機械的な繰り返しを避ける | 可(レーン列 n-gram) |
| 強拍優先 | 低難易度ほど強拍にノーツを置く | 可(拍位置の分布) |
| 難易度の一貫性 | easy は hard の骨格。同じ箇所で同じ音を叩く | 部分的に可 |

調査の結果、名前や中身は入れ替わってよい。この表は粒度の見本であって確定リストではない。

## 検査の拡張

初期は 2〜3 個だけ `verify()` 系に追加する。候補:

1. セクション別密度が `SECTIONS` の倍率カーブと整合しているか
2. オンセット整合率(ノーツが音のオンセット近傍に乗っている率)
3. 強拍配置率(低難易度ほど強拍にノーツが集まっているか)

実行タイミングの使い分け:

- 音由来の検査(オンセット整合)は mp3 解析が必要なので **bake 時のみ**実行
- JSON 単体で判定できる検査(密度カーブ、強拍率)は `--verify` でも実行

既存の「bake は全検査、`--verify` は JSON 検査」という構造を保つ。

## SKILL.md の手順

1. `uv run scripts/bake-chart.py --verify` で現状診断
2. 違反ゼロでも charts.json を theory.md の原則に照らして定性診断
   (検査化できていない原則のため)
3. 直すべき点を bake-chart.py のパラメータ / ロジック変更に翻訳する
4. 再 bake → 検査。パスするまで 3-4 を繰り返す
5. 変更前後の差分(密度カーブ、違反の増減)をサマリして報告

譜面 JSON は生成物なので直接編集しない(既存ルールを維持)。

## AGENTS.md の変更

- 「ゲームロジック(判定・スコア・描画)は…ブラウザで実際に遊んで確認する」の文言を削除
- 代わりに「譜面の改善は chart-feel スキルを使う。合格基準は bake-chart.py の検査」を追記

## スコープ外

- 新規スクリプトの追加
- 譜面 JSON の直接編集
- エージェント化(改善ループが十分機械的になったら、スキルを呼ぶ薄い
  エージェント定義を後から足せる)
- 他曲・他ゲームへの汎用化

## 完了条件

- theory.md に原則 5〜7 個が蒸留されている
- verify() に理論由来の検査が 2〜3 個入り、現行譜面で bake → 検査が通る
  (通らない場合は bake-chart.py を調整して通す)
- SKILL.md の手順どおりに一周回して、改善ループが機能することを確認済み
- AGENTS.md が更新済み
