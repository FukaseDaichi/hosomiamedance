# 実音源「ホソミアメダンス」への差し替え・難易度3種・歌詞表示 — 設計

作成日: 2026-08-14

## 目的

SUNO で生成した実音源 `ホソミアメダンス.mp3` をゲーム本編の曲にする。合成 3 曲を廃止し、
この 1 曲に EASY / NORMAL / HARD の 3 難易度を用意する。あわせて歌唱に同期した歌詞を画面に表示する。

## 設計

### 1. 音源ファイル

`public/assets/ホソミアメダンス.mp3` を **`public/assets/hosomiamedance.mp3` にリネームする。**
GitHub Pages 配信で日本語ファイル名は URL エンコードが必要になり、環境によって取り違えが起きる。
参照は `import.meta.env.BASE_URL` を前置する（AGENTS.md の規約）。

サイズ 3.3 MB。GitHub Pages の制限内で、リポジトリに直接コミットする。

### 2. 再生方式

`<audio>` 要素ではなく **`decodeAudioData` → `AudioBufferSourceNode`** で鳴らす。

理由: 現在の判定は `ctx.currentTime - startAt` を時計にしている（`src/audio.ts` の `time()`）。
`<audio>` の `currentTime` はブラウザによって数十 ms 単位で量子化・ジッタが乗るのに対し、
AudioBuffer 再生なら同じ時計のままサンプル精度で一致する。既存の判定ロジックを変更せずに済む。

読み込みの流れ:

1. `App` のマウント時に mp3 の `fetch` を開始する（AudioContext 不要）
2. ユーザー操作で `wake()` が呼ばれた後に `decodeAudioData` する
3. 選曲時にデコード未完了なら `loading` 表示で待ち、完了後に再生を開始する

`startSong()` は `AudioBufferSourceNode` を `master` に繋いで `start(startAt)` する。
`startAt = ctx.currentTime + 0.9`（現行の助走時間を踏襲）。
先読みスケジューラ（`setInterval` によるノート予約）は不要になるので削除する。

### 3. audio.ts の再構成

残すもの: `ensureEngine` / 雨音 / `sfx` / `wake` / `setRain` / `time` / `stop`。

削除するもの: `mulberry32` / `PENTA_MAJ` / `PENTA_MIN` / `SONG_DEFS` / `buildEvents` /
`pluck` / `kick` / `hat` / `bass` / 先読みスケジューラ / `SongDef`・`Song`・`NoteEvent` 型 /
`SONGS` エクスポート。合成曲エンジン一式。

`SONGS` は `DIFFICULTIES` に置き換わる。`App` の `state.songIdx` は `DIFFICULTIES` の
インデックスとして引き続き使い、`HAudio.SONGS[i].name` の参照箇所を差し替える。

`sfx` 内の `ding` はそのまま使う（効果音は合成のまま）。

新しく持つもの:

```ts
export interface Difficulty {
  id: 'easy' | 'normal' | 'hard'
  name: string        // 'EASY' など
  desc: string        // 'はじめての アメダンス' など
  hearts: number      // 1..3
  noteSpeed: number   // px/s
  perfWindow: number  // 秒
  goodWindow: number  // 秒
}
export const BPM = 156
export const DIFFICULTIES: Difficulty[]
export function chart(id: Difficulty['id']): ChartNote[]
```

`ChartNote` は現行の `{ t, lane }` のまま。`App` 側の判定・描画コードは変更不要。

### 4. 譜面のベイク

`scripts/bake-chart.py`（uv / PEP 723、依存は librosa・numpy）で mp3 を解析し、
`src/charts.json` を生成してリポジトリにコミットする。ブラウザ側は JSON を import するだけ。

手順:

1. BPM・拍位相・小節線は上記の実測値を**定数として持つ**。スクリプト内で再探索しない
2. 16分グリッド（全 1416 点）で帯域別オンセット強度を算出する
   - 低域 30–160 Hz（キック）
   - 中低域 160–400 Hz（スネア胴）
   - 中域 300–3000 Hz（メロディ・ボーカル）
   - 高域 4–10 kHz（ハイハット・クラップ）
3. 各グリッド点を **キック / スネア / ハイハット / メロディ** のいずれかに分類する
4. 難易度ごとに、使用グリッド（4分・8分・16分）と区間別の目標密度に従い、
   強い点から順に採用する。制約は 2 つ
   - 全レーン通しての最小間隔: EASY は 4分（0.385 s）、NORMAL は 8分（0.192 s）、HARD は 16分（0.096 s）
   - 同一レーンの最小間隔: 全難易度で 8分（0.192 s）
5. レーン割り当ては音の種類で決める
   - キック → **↓**（lane 1）
   - スネア・クラップ → **↑**（lane 2）
   - メロディ → 直前の採用ノートより音程が高ければ **→**（lane 3）、低ければ **←**（lane 0）
   - ハイハットは HARD の埋め草のみ。直前と異なるレーンに交互に振る

レーンを乱数で散らさず音の種類に固定するのは、キックが必ず↓に来ることを体が覚えると
気持ちよくなるため。ただし同一レーンが 3 連続以上続く場合は 1 つ隣にずらす。

#### 固定ギミック

小節 56–62 のブレイクで「ひだり みぎ うえ した」と歌う 4 語の頭に、
**←→↑↓ のノーツを歌詞どおりの順で 1 個ずつ**置く。自動生成の対象外とし、
スクリプト内にハードコードする。3 難易度とも共通。

該当語の発声時刻は ASR では「左右」が 1 トークンに結合してしまい、
`ひだり ≈ 92.26 s` / `みぎ` 不明 / `うえ ≈ 94.64 s` / `した ≈ 95.16 s` までしか取れていない。
**実装時に 92–96 秒の中域オンセットを個別に検出して 4 点を確定させること。**
この区間はキックが抜けているので、中域のオンセットはほぼボーカルのみで拾えるはず。

### 5. 難易度パラメータ（初期値）

| | 使用グリッド | 想定ノーツ数 | 落下速度 | perfect 窓 | good 窓 | ♥ |
| --- | --- | --- | --- | --- | --- | --- |
| EASY | 4分中心 | 約 160 | 260 px/s | ±0.090 s | ±0.190 s | 1 |
| NORMAL | 8分 | 約 280 | 320 px/s | ±0.070 s | ±0.150 s | 2 |
| HARD | 8分＋16分連打 | 約 460 | 400 px/s | ±0.055 s | ±0.120 s | 3 |

区間別の密度倍率は「曲の構成」表の「譜面の扱い」列に従う。
アウトロ（小節 86 以降）にはノーツを置かない。

**これらは実際に遊んで調整する前提の初期値である。** 数値の最終決定はブラウザでの試遊による。

`AppProps` の `noteSpeed` は難易度の基準値に対する倍率、`easyJudge` は判定窓を広げる
オーバーライドとして残す。

### 6. 曲リストの入れ替え

選曲画面は「ホソミアメダンス EASY / NORMAL / HARD」の 3 枚になる。
合成 3 曲（あめあがりマーチ / みずたまりポップ / かみなりビート）は削除する。

`song-card` の表示は BPM 156 固定、`song-name` は難易度名、`song-desc` はひらがなの説明文。
数字キー 1・2・3 での選択は現行のまま維持する。

`RainStage.setBPM(156)` を渡す。

### 7. 終了判定

現在は「最後のノーツ + 2.4 秒」で結果画面に遷移している。実音源では**曲の終わり
（約 136.9 秒）まで待ってから**遷移し、アウトロのフェードを聴かせる。
`endAt = 137.0` を定数で持つ。

### 8. 歌詞表示

`src/lyrics.ts` に `{ t: number, end?: number, text: string }[]` を持つ。

- 表示テキストは**こちらが書いたひらがなの原文**を使う。ASR の結果（漢字混じり）は時刻の取得にのみ使用する
- 行の表示は次の行の `t` まで
- 次の行まで間が空く行には `end`（歌い終わりの時刻）を入れ、`end + 0.3 秒`で消す。
  該当するのは 3 行だけ: 24.24（→ 26.64、このあと間奏）、117.88（→ 120.66）、128.80（→ 132.90、最終行）
- 間奏（26.9–37.9 秒）とアウトロ（133.2 秒以降）は何も表示しない

固定の上限秒（「N 秒経ったら消す」）にしないのは、行ごとに歌う長さが 2.5〜4 秒とばらつくため。
上限秒だと短い行は消えるのが遅れ、長い行は歌い終わる前に消える。

表示位置は画面左下、`.hint` の上。レーンパネル（`right: 30px`, `width: 340px`）を避け、
左側の余白に置く。切り替えは 0.25 秒のクロスフェード。**前の行をフェードアウトさせるため、
消えていく行と現れる行の 2 要素を同じ座標に重ねて描く。**新しい行のフェードインだけでは
前の行が瞬間的に消えてクロスフェードにならない。

毎フレームの `setState` を避けるため、`loop()` 内で現在の行インデックスを計算し、
**インデックスが変化したときだけ** `setState` する。

## 検証

型チェックとビルド（`npm run build`）は通すが、それだけでは不十分。
判定・スコア・描画は挙動が繊細なため（AGENTS.md）、以下をブラウザで実際に遊んで確認する。

1. 3 難易度すべてで最後まで通しプレイし、ノーツが音とずれていないこと
2. 小節 56–62 の「ひだり みぎ うえ した」で ←→↑↓ が歌詞どおりの順に来ること
3. 歌詞の切り替えが歌唱から遅れて見えないこと
4. 間奏とアウトロで歌詞が消えていること
5. 曲の雨音とゲームの雨音が重なって濁っていないこと（濁る場合は `setRain` の基準値を下げる）
6. リロード直後の初回プレイで、デコード待ちがハングして見えないこと

## 未確定・あとで決めること

- 難易度の数値（ノーツ数・落下速度・判定窓）は試遊後に調整する
- 曲の雨音とゲームの雨音の音量バランスは試遊後に決める
- 「ひだり みぎ うえ した」4 語の正確な発声時刻は実装時にオンセット検出で確定させる
