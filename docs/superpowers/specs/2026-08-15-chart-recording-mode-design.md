# 譜面録音モード(dev限定)設計書

2026-08-15

## 目的

譜面を「実際の画面で音楽に合わせて十字キーを叩いて」作れるようにする。
録音した入力を Claude がタイミング補正・整形して3難易度の譜面に展開する。
現在の全自動生成(bake-chart.py)より、人間のグルーヴ感覚を強く反映した
「本当に面白い譜面」を作るための開発者向け機能。ローカル起動時のみ有効。

## 決定事項

- 録音は **hard 相当の理想グルーヴを1本、通しで1発録り**。normal/easy は Claude が展開する
- 録音画面は **まっさらなレーン+拍マーカー**(既存譜面のゴースト表示はしない)
- タイミング補正・整形・難易度展開は **全部 Claude がやる**(決定的スクリプトにしない)
- **charts.json 直接編集禁止の規約は改訂**し、録音由来の譜面は Claude が書く道を作る
- 録音データ(recordings/)は git 管理する。譜面の出自として残す資産

## 全体フロー

```
録音モードでプレイ(dev サーバー)
  → POST /__rec で recordings/<曲ID>-<日時>.json に自動保存
  → Claude に「この録音を譜面にして」と依頼
  → Claude が chart-feel スキルの手順で量子化・整形・3難易度展開
  → src/charts.json のその曲を書き換え(source: "recorded")
  → プレイして確認
```

## 1. 録音モード(フロントエンド)

### 入口

- `import.meta.env.DEV` のときだけ、難易度選択画面(`phase === 'select'`)に
  4枚目のカード「🎙 譜面をつくる」を出す。キー `0` でも入れる
- 本番ビルドでは `import.meta.env.DEV` が `false` 定数に置換されるため、
  分岐ごと dead code elimination で消える

### 録音画面

- 通常ゲームと同じ構成: 雨ステージ+キャラ(踊る)+レーンパネル
- ノーツの代わりに**拍線**が判定ラインへ流れてくる
  - 拍 = 細い横線、小節頭 = 太い線+小節番号
  - 時刻は `charts.json` の `beat0` と `bpm` から計算(拍間隔 = 60/bpm)。
    小節頭の位相には `bar0` を使う(bake-chart.py が新たに書き出す。後述)
- 落下速度は hard の `noteSpeed` 固定(録音対象が hard 相当のため)
- 十字キー keydown で記録: `HAudio.time()`(出力遅延補正済みの「耳の時計」)と
  レーン番号。判定・スコア・コンボは無し
- 押すたびにレーンフラッシュ+短いティック音でフィードバック
- HUD: 現在小節 / 叩いた数 / 経過秒 の小さな表示のみ

### 終了と保存

- `songEnd` に達したら自動で録音完了 → 保存
- **Esc は「そこまでを保存して終了」**(前半だけ録って使う、が自然にできる)。
  このとき `aborted: true` と中断時刻 `endT` を記録する
- 保存成功: 「ほぞんしたよ → recordings/amagoi-20260815-103045.json」と表示して
  難易度選択へ戻る
- 保存失敗(dev サーバー無し等): エラー表示し、コンソールに録音 JSON を
  丸ごと出力して救済する

### 録音データ形式

```jsonc
// recordings/amagoi-20260815-103045.json
{
  "song": "amagoi",
  "recordedAt": "2026-08-15T10:30:45+09:00",
  "bpm": 127.384,        // 再現・検証用に charts.json から転記
  "beat0": 0.294,
  "aborted": false,      // Esc 中断なら true
  "endT": 164.0,         // 録音が有効な範囲の終わり(中断時は中断時刻)
  "taps": [[1.842, 2], [2.315, 0]]  // [耳の時計での秒, レーン 0..3] 昇順
}
```

## 2. 保存経路(Vite dev プラグイン)

- `vite.config.ts` にインラインプラグイン(20行程度)を追加
- `configureServer` フックで dev サーバーに `POST /__rec` を生やし、
  リクエストボディをリポジトリ直下 `recordings/` に書く
- ファイル名はサーバー側で `<曲ID>-<YYYYMMDD-HHmmss>.json` に決める
  (クライアントに任せずパストラバーサルの余地を無くす)
- `configureServer` は dev 限定フックなので、本番ビルド・preview には一切入らない

## 3. Claude 変換フロー(chart-feel スキルに追記)

`.claude/skills/chart-feel/` に「録音→譜面」の手順を追記する。骨子:

1. **読む**: 録音 JSON と bake-chart.py の `SONGS` 実測定数(bpm / beat0 / bar0 /
   last_bar / sections)
2. **量子化**: 各タップを16分グリッド(spb/4)の最寄りに寄せる。人間の入力は
   系統的に遅れる傾向があるため、全タップの中央値オフセットを先に引いてから
   量子化する
3. **掃除**: 同グリッド同レーンの重複除去、物理的に叩けない間隔
   (同レーン < 16分×2 など、既存の gap 基準を参考)の整理
4. **hard 確定**: 掃除後のタップ列をそのまま hard とする
5. **normal/easy 展開**: 小節ごとのリズムパターン(骨格)を保ったまま間引く。
   目標ノーツ数は既存の notes/sec 基準(easy 1.204 / normal 2.107 /秒)を参考に、
   録音の実ノーツ数との整合を優先する
6. **書き込み**: `src/charts.json` のその曲の `notes` を書き換え、曲メタに
   `"source": "recorded"` を付ける
7. **検査**: `uv run scripts/bake-chart.py --verify` を通す
8. **最終判定はプレイ確認**(既存の規約どおり)

## 4. bake-chart.py との共存

- charts.json の曲メタに `source` フィールドを導入:
  `"baked"`(従来の自動生成)/ `"recorded"`(録音由来・Claude 整形)。
  既存データは次回 bake 時に `"baked"` が付く
- **全曲生成時**(引数なし)は `source: "recorded"` の曲をスキップして警告を出す
- **曲ID明示指定時**(`bake-chart.py amagoi`)は recorded でも上書き生成する
  (自動生成に戻す道)。上書きした旨を出力する
- `--verify` は recorded の曲には最低限の健全性チェックのみかける:
  - タップ時刻が昇順
  - レーンが 0..3
  - 同レーンの最小間隔・全体の最小間隔(叩ける速さか)
  - ノーツが `bar0` 〜 `last_bar` の範囲内
  - 難易度の忙しさが easy ≤ normal ≤ hard の順序
  - 従来の「生成の意図どおりか」系の検査(sections 密度など)は**かけない**
- bake-chart.py は `bar0` も charts.json に書き出すようにする(拍線描画用)。
  このため導入時に一度全曲を bake し直す

## 5. AGENTS.md の改訂

- 「`src/charts.json` は生成物なので直接編集しない」を改訂:
  - baked の曲: 従来どおり bake-chart.py で生成、直接編集しない
  - recorded の曲: 録音フロー(chart-feel スキルの手順)で Claude が書く。
    手編集ではなく必ず手順を通す
- 録音モードと recordings/ の説明を構成表に追記

## 6. スコープ外(YAGNI)

- ブラウザ内での譜面編集・プレビュー・シーク
- 区間ごとの録り直し(punch-in)。つらくなったら後から足す
- 複数テイクの自動マージ(使い分けは Claude 変換時に依頼ベースでやる)
- 本番ビルドへの録音機能の同梱

## 7. 検証

- `npm run build` 通過(型 + 本番ビルド)
- 実機での一周確認: 録音 → recordings/ に保存 → Claude 変換 →
  `--verify` 通過 → 実プレイで音と合っているか確認
- 本番ビルドに録音モードが混入していないこと(`dist/` に `__rec` /
  「譜面をつくる」の文字列が無いこと)を確認
