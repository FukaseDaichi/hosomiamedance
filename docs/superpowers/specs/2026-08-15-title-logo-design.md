# タイトルロゴの導入

## 目的

タイトル画面の「ホソミ / アメダンス」は今テキストで、いろは餅フォントに
text-shadow で厚みを付けている。これを描き起こしのロゴ画像に差し替える。
併せてローディング画面・ファビコン・OGP にも同じロゴを行き渡らせ、
どこから来ても同じ顔に見えるようにする。

見出し（「きょくを えらぼう」等）の色やトーンは今回の対象外。

## 原本

`logo-src.png`（1672x940、RGBA）をリポジトリ直下に置いてコミットする。
`hosomi.mp4` と同じく「生成物の原本は git に置く」方針に合わせる。

アルファは実体を持つ（完全透明 41.7%、四隅 0、境界はなめらかな中間値）。
暗背景に乗せて拡大しても縁は破綻しない。ロゴ本体のアルファは 255 ではなく
253 前後だが、0.8% の透過は見た目に出ないのでそのまま使う。

傘のある初版もあったが採用しない。しずく・泡・きらめき版（濃いピンクと紫、
太い白フチ）のほうが暗背景でのコントラストが強く、縮小しても文字が読める。

## 生成物

`scripts/bake-logo.py`（uv + Pillow）で 4 つ作る。`npm run bake-logo` を
package.json に足す。既存の bake-sprites / bake-chart と同じ形。

| 生成物 | 用途 | 中身 |
| --- | --- | --- |
| `public/assets/logo.webp` | タイトル・ローディング | 幅 1280px、透過維持 |
| `public/assets/ogp.png` | SNS シェア | 1200x630、背景 `#2a2347` に焼き込み。OGP は透過非対応 |
| `public/favicon-32.png` | ブラウザのタブ | 「ホ」を切り出し |
| `public/favicon-180.png` | iOS のホーム画面 | 同上 |

幅 1280px は、タイトルの最大幅 620px を 2 倍の画面密度で出しても足りる寸法。
原本の 1672px をそのまま配るより軽い。

ファビコンは「ホ」の一文字。背後にロゴのピンク（`#f5b8d4` 系）の角丸ベタを
敷く。「ホ」はクリーム寄りの淡色なので、白いタブバーだと輪郭が溶けるため。
切り出し座標はスクリプトの定数に置き、生成結果を見て詰める。

## 画面の変更

**タイトル画面**（`src/App.tsx`）。`.title-text` のテキスト 2 行を `<img>` に
置き換える。`alt="ホソミアメダンス"`。

- サブコピー「あめのひは みずたまりで ダンス!」は残す。ロゴだけだと
  何のゲームか分からないため
- `.title-block` の `floaty`（3.2 秒でふわふわ）はそのまま効く
- 幅は `min(86vw, 620px)`
- ロゴが白フチと影を持っているので CSS の text-shadow は不要。
  暗背景から浮かせる軽い `drop-shadow` だけ足す

**ローディング画面**。「じゅんびちゅう…」の上にロゴを `min(64vw, 400px)` で
出す。タイトルへの繋がりになる。ロゴ画像はスプライト 128 枚より圧倒的に軽く、
読み込み待ちにはならない。

**index.html**。ファビコン 2 種と OGP メタ（`og:title` / `og:description` /
`og:image` / `og:url` / `twitter:card=summary_large_image`）を足す。
`og:image` は絶対 URL が要るので
`https://fukasedaichi.github.io/hosomiamedance/assets/ogp.png` を書く。

## 落とし穴

- **base パスは `/hosomiamedance/`**。`src/App.tsx` の img は
  `import.meta.env.BASE_URL` を前置する（AGENTS.md）。index.html 内の
  ファビコンのパスは Vite の書き換え結果が読めないので、
  ビルド後に `dist/index.html` を実際に見て確認する
- **原本を `public/` に置かない。** `public/` 配下はビルド後もそのまま
  配信されるので、1.5MB の PNG がそのまま本番に載ってしまう。原本は
  リポジトリ直下、配信するのは bake した `public/assets/logo.webp` だけ
